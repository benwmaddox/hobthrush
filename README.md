# lang

`lang` is a temporary working name for an agent-first general-purpose language under construction; the permanent name is pending. The executable is `lang` and source files use `.lang`. This repository is independent of Stasis.

This is an early, pre-1.0 implementation. Language syntax, APIs, CLI behavior, manifests, lockfiles, and generated metadata may change without backward compatibility or migration support. Schema numbers identify the current format for tooling and test assertions; they do not promise support for historical formats. Update the compiler, consumers, examples, tests, and documentation together, and regenerate derived artifacts after format changes.

The implemented language slice supports `i32`, `bool`, `Text`, immutable nominal structs (including generic structs), declared tagged unions (including generic tagged unions), generic functions with argument-based type inference and minimal pure static traits, `Option<T>`, `Result<T, E>`, exhaustive `match`, scoped `if`/`else`, comparisons, and checked arithmetic. Generic struct and union constructors require their type arguments explicitly; match patterns take their type arguments from the scrutinee. Trait signatures are bodyless and pure, use implicit `Self`, and bind through explicit closed implementations to existing pure functions. Ordered function type-parameter bounds support qualified statically dispatched calls and witness forwarding. Trait objects, generic impls, associated types, inheritance, and operator overloading are outside this slice. `Text.length` counts Unicode scalar values and `Text.trim()` removes leading and trailing Unicode whitespace. Every function declares an upper bound with `effects { ... }`; the compiler checks inferred direct and transitive effects against it. Implemented effectful operations are `FsRead.read_text` and `FsRead.read_text_async` (`fs.read`), `FsWrite.write_text` and `FsWrite.write_text_async` (`fs.write`), `HttpClient.get_text_async` (`net.client`), bounded SQLite operations (`DbRead.query_one` for `db.read`; `DbWrite.execute`, `DbWrite.begin`, `Transaction.execute`, and `Transaction.commit` for `db.write`), and the pinned CLI `ProcessRunner.run_text_async` (`process.spawn`). Filesystem, database, network, and process operations use opaque capability values and root-package grants. These checks describe compiler and trusted-host metadata; they are not a security sandbox or a proof of adapter behavior. See [docs/grammar.md](docs/grammar.md) for the syntax and limits.

Nongeneric nominal newtypes wrap one declared representation, require explicit `QualifiedType.wrap(value)` construction, and expose only the `.value` projector. They do not implicitly convert or forward arithmetic, ordering, or traits; equality follows the wrapped value's supported structural semantics while preserving nominal type boundaries. Stored resource handles and direct by-value cycles are rejected, guarded recursive values remain supported, and route/SQLite codecs reject newtypes during checking.

The first startup configuration slice adds root-only `[config]` declarations and the `env.read`, `secret.reveal`, and `log.write` grants. CLI handlers and web routes can receive `Config`, `Secrets`, and `Logger` services. Configuration is snapshotted once before a CLI handler starts or a web listener opens. API schema v11 and audit schema v9 expose configuration field names, source types, and required/default status without runtime values or default literals; API schema v11 records struct and union type parameters and recursive nominal type arguments. The first slice has no dynamic reload or secret rotation, arbitrary logging maps or sinks, clock/timestamp service, or end-to-end secret taint tracking.

Contextual `async fn` and `pub async fn` functions use `await` only for async calls or intrinsics inside an async function. Source signatures retain their declared result type `T`; generated code uses hidden task and cancellation-token plumbing. `FsRead.read_text_async` decodes strict UTF-8 and contributes `fs.read`; `FsWrite.write_text_async` stages a strict-UTF-8 write beside the destination and contributes `fs.write`; `HttpClient.get_text_async` contributes `net.client`, uses a manifest-pinned origin, and propagates host cancellation. The synchronous filesystem APIs remain available. SQLite remains a synchronous source API; an async SQLite surface is deferred pending a meaningful concurrency and cancellation design. Generic structs and unions are supported in ordinary library and application code, with all constructor type arguments stated explicitly and no constructor inference; generic function calls continue to infer type arguments from their arguments. Route reply unions must be nongeneric, and unsupported generic JSON body/response or SQLite parameter/row codec shapes are rejected during source checking.

The bounded collections slice adds contextual immutable `List<T>` with homogeneous literals, `length`, `get(i32) -> Option<T>`, and copy-on-write `append`; an empty `[]` needs an expected `List<T>` type. `Text.split(separator)` uses the exact delimiter and preserves empty fields; an empty separator returns a singleton containing the original text. `for item in list` visits items in order with a scoped immutable binding, and calls in the loop body contribute to the function's inferred effects. Typed `var` locals can be rebound to the same type; `let` locals and loop bindings cannot. It also adds contextual `Map<Text, V>` with `Map.empty()` requiring an expected map type, immutable `set(Text, V)`, `get(Text) -> Option<V>`, `keys() -> List<Text>` in ordinal key order, and `length: i32`. Each `set` returns a new snapshot, so earlier maps retain their entries. Values containing resource handles, directly or through struct/union fields or payloads, cannot be stored in lists, map values, or rebindable `var` locals; this does not prevent declaring and directly constructing such immutable nominal values. Qualified user types named `List` and `Map` remain valid. Map literals, removal, non-Text keys, index syntax, list mutation, `break`, and `continue` are not implemented.

Install the .NET 10.0.401 SDK, then from this directory:

dotnet run --project src/Lang --configuration Release -- run examples/types/src/main.lang
dotnet run --project src/Lang --configuration Release -- run examples/structs/src/main.lang
dotnet run --project src/Lang --configuration Release -- lock examples/library-package
dotnet run --project src/Lang --configuration Release -- check examples/library-package
dotnet run --project src/Lang --configuration Release -- build examples/library-package
dotnet run --project src/Lang --configuration Release -- run examples/library-package
dotnet run --project src/Lang --configuration Release -- check examples/text-validation
dotnet run --project src/Lang --configuration Release -- build examples/text-validation
dotnet run --project src/Lang --configuration Release -- test examples/text-validation
dotnet run --project src/Lang --configuration Release -- lock examples/scan-cli
dotnet run --project src/Lang --configuration Release -- check examples/scan-cli
dotnet run --project src/Lang --configuration Release -- build examples/scan-cli
dotnet run --project src/Lang --configuration Release -- audit examples/scan-cli --json
dotnet run --project src/Lang --configuration Release -- run examples/scan-cli -- scan ./input.txt --normalize

dotnet run --project src/Lang --configuration Release -- check examples/web

dotnet run --project src/Lang --configuration Release -- test
dotnet run --project tests/Lang.IntegrationTests --configuration Release

`lang check FILE` checks the source and returns 1 for invalid programs. `lang check FILE --json` prints stable diagnostic codes, source ranges, and severity, including an empty diagnostics array on success. `lang test FILE_OR_PACKAGE` typechecks and runs the source's managed language tests. Bare `lang test` keeps the compiler fixture mode and compares all 104 currently active fixtures against their exact expected ordered diagnostic-code lists.

Arbitrary CLR imports are not supported. The bounded managed .NET SHA-256 text adapter is implemented: the compiler validates its pinned assembly bytes and metadata, and generated applications load and call that catalogued assembly in-process with full process authority. This does not expose arbitrary assembly members or make the adapter a sandbox. The separate narrow C ABI proof remains planned; see [docs/foreign-interop.md](docs/foreign-interop.md).

Agent-oriented outcome evaluation runs separately from `lang test` and records three task-card results with raw command evidence; see [docs/agent-evals.md](docs/agent-evals.md).

A possible future public maintenance model is described in the non-binding [public AI-operated stewardship proposal](docs/public-ai-stewardship.md). It uses ordinary sponsorship, paid review, milestone funding, public accounting, and independent technical gates. It explicitly excludes cryptocurrency, tokens, tradable governance rights, financial-return promises, and pay-to-merge decisions.

`lang build FILE` compiles a program with a supported `main() -> i32|bool|Text` or one typed command declaration as an executable. If both entry forms are absent, it builds a library DLL. Command builds also emit `command-schema.json` beside the executable. Artifacts are stored in a unique `out/<source-name>-<id>/` directory beside the input file. `lang run FILE` runs the supported main entry; `lang run FILE -- APPLICATION_ARGS` dispatches application arguments to a source file's typed command. Main runs print their returned value and a newline, and exit 0 on success. Checked i32 arithmetic overflow reports a generic runtime fault and exits 70.

`lang check PACKAGE_DIRECTORY`, `lang build PACKAGE_DIRECTORY`, and `lang run PACKAGE_DIRECTORY` load a package from its root `lang.toml`. The package slice supports `lib`, `cli`, and managed `web` manifests, module files under the declared `source_root`, fully qualified declaration references, local path dependencies, and exact-commit Git dependencies on library packages. A CLI package names one `entry_module`; that module may provide the existing supported `main() -> i32|bool|Text` or one typed command declaration. A web package names one route entry module, grants `net.listen`, and runs a managed ASP.NET host. `lang run WEB_PACKAGE -- --urls URL` forwards the URL option to the host. A library package has no entry module. `lang new lib|cli|web NAME` creates a validated starter package under the current directory and refuses an existing target. `lang add SOURCE` updates the current package; `lang add PACKAGE_DIRECTORY SOURCE` selects one explicitly. `SOURCE` is a local relative package path, or an exact Git URL ending in `#` plus a 40-character lowercase commit; Git URLs are HTTPS or file URLs. The command derives the dependency alias from its package name and updates the manifest and lock. For Git sources, `lang add` and `lang lock` freshly fetch and verify the exact pin before updating the manifest or writing a lock; a mismatched existing cache is rejected without changing the cache or lock. The package cache defaults to the user local-application-data directory under `lang/packages`, or can be selected with `LANG_PACKAGE_CACHE`. An explicit cache equal to or inside the package root or its `source_root` is rejected before source discovery. Git cache keys use the canonical URL and exact commit. Offline commands validate the current project lock and recompute cached content against its attestation and pinned URL/commit; the unkeyed attestation is a local integrity record, not proof of upstream Git provenance. `check`, `build`, `run`, `test`, `inspect effects`, `inspect api`, and `audit` validate the current project lock and cache offline and never invoke Git; they fail with guidance to run `lang lock` if a pin is absent or invalid. A Git-sourced package cannot declare local path dependencies. The examples in [`examples/library-package`](examples/library-package), [`examples/scan-cli`](examples/scan-cli), and [`examples/web`](examples/web) demonstrate package dependencies and their respective entry forms.

Package manifest fields use TOML string values. CLI packages may grant `fs.read`, `fs.write`, `net.client`, `env.read`, `secret.reveal`, `log.write`, and/or `process.spawn` with the exact string value `"allow"`; `net.client` requires top-level `http_origin`. Web packages require `net.listen` and may also grant `fs.write`, configured `db.read`/`db.write`, `net.client`, `env.read`, `secret.reveal`, and/or `log.write`; `net.client` also requires `http_origin`. The origin is one absolute HTTPS origin, or HTTP for `localhost` or a loopback IP, with only a root path and no query, fragment, or user info. SQLite-enabled web packages declare both `sqlite_path` and `sqlite_schema` as normalized, package-relative paths and grant `db.write` for schema initialization; root web database grants require this configuration. Library packages may expose checked functions with `DbRead`, `DbWrite`, or `HttpClient` parameters without application grants; a library using database operations includes the SQLite provider dependency when built. Declare the root `[config]` table before `[capabilities]` and `[dependencies]`; `[dependencies]` remains the final manifest section. A library cannot declare application capabilities or use or expose the first-slice `Config`, `Secrets`, `Logger`, and `Secret<Text>` types.

Each `[config]` key uses lower_snake_case and a descriptor string of `Text|required`, `Text|default:<literal>`, or `Secret<Text>|required`. An empty `Text|default:` is a valid default. A field named `api_token` reads `LANG_CONFIG_API_TOKEN`; required means the variable must be present, and an empty present value is valid. Defaults are used when their environment variable is absent. The host snapshots values once before invoking a CLI handler or starting the web listener. A missing required value reports only the config field and environment variable names; CLI startup exits 78, and web startup fails before listening.

`Config.get_text` and `Config.get_secret_text` require a literal key declared with the matching descriptor. `Secrets.reveal_text` is the only reveal operation and contributes `secret.reveal`; it returns ordinary `Text`, which has no taint tracking. Source code cannot construct a `Secret<Text>` wrapper. `Secret<Text>` is redacted by standard formatting and `Logger.info`. `Logger.info(event, detail)` contributes `log.write` and writes one deterministic JSON line to stderr with `level`, `event`, and `detail`, plus `request_id` when available in a web request. Metadata and grants do not provide OS-level containment.

A CLI root may grant `process.spawn` only when it declares complete top-level `process_windows_path`/`process_windows_sha256` and/or `process_linux_path`/`process_linux_sha256` pairs before the manifest tables. Every declared pin path must be normalized and root-contained, and its file must exist as a regular non-symlink/non-reparse file whose SHA-256 matches on every host. A process pin requires the root CLI `process.spawn` grant, and that grant requires a current-host pair. The selected Linux executable must also have an execute permission bit. The selected executable is copied beside the generated CLI artifact as `<manifest assembly name>.process-runner` on Linux or `<manifest assembly name>.process-runner.exe` on Windows, preserving its execute bit. This deterministic suffix avoids colliding with the generated apphost when the application assembly is named `process-runner`; identity is checked again immediately before spawn. Audit inputs include every declared executable. API schema v11 and audit schema v9 list configured pins in `process_executables` after `http_origin`, Windows then Linux, as `{ os, path, sha256 }` records with relative paths.

`ProcessRunner`, `ProcessOutput`, and `ProcessError` are opaque types scoped to the root CLI package; `ProcessRunner` is injected after `Logger`, and same-package helper functions may accept and pass it. Await `runner.run_text_async(arguments: List<Text>, stdin: Text) -> Result<ProcessOutput, ProcessError>`. `ProcessOutput` contains `exit_code: i32`, `stdout: Text`, and `stderr: Text`; the closed, zero-payload `ProcessError` variants are `InvalidArgument`, `InputTooLarge`, `OutputTooLarge`, `InvalidText`, `StartFailed`, and `TimedOut`. A nonzero child exit is still `Ok(ProcessOutput)`. The runner invokes only the copied absolute executable, with shell disabled, no `PATH` search, `ArgumentList` arguments, an empty environment, and the artifact directory as its fixed working directory; callers cannot choose the executable, environment, or working directory. A Windows launch incompatibility maps to `StartFailed` without shell fallback. It accepts at most 128 arguments, 16 KiB combined strict-UTF-8 argument bytes, and 1 MiB strict-UTF-8 stdin; each raw output stream is capped at 1 MiB and decoded as strict UTF-8, with a fixed 10-second overall timeout. Host cancellation propagates after best-effort process-tree termination and a reap bounded to two seconds. These pins and grants are metadata and invocation constraints, not OS containment: the selected binary retains full OS authority. The slice has no web support, streaming, dynamic executable selection, binary I/O, per-call timeout, detached-work API, CPU/memory sandbox, or guarantee that detached descendants are killed.

```toml
name = "validation-example"
version = "0.1.0"
kind = "cli"
source_root = "src"
entry_module = "app::main"

[config]
api_token = "Secret<Text>|required"
environment = "Text|default:local"

[capabilities]
env.read = "allow"
secret.reveal = "allow"

[dependencies]
validation = "../text-validation"
```

For `kind = "lib"`, omit `entry_module`; for `kind = "cli"` and `kind = "web"`, it is required. Module paths and entry modules use `::`: `module app::main;` belongs in `src/app/main.lang` when `source_root = "src"`, and its manifest entry is `app::main`. User declarations always use a qualified reference with a root, module path, and declaration name. Use `self::catalog::message::Greeting` for a declaration in the current package, or `validation::text::validation::NormalizeError` for a declaration in the directly declared `validation` dependency. The alias `self` is reserved and cannot be used as a dependency alias; bare `self` follows ordinary local-name rules and is a namespace root only when followed by `::`. Aliases name only direct dependencies and are not re-exported transitively. `::` separates namespace components; `.` remains for value fields, member operations, and union variants, as in `self::catalog::message::Message.Ready(value)`. Built-in types and constructors such as `Option<T>`, `Some`, `None`, `Ok`, `Err`, and `FsError` keep their short forms. Local variables also remain ordinary unqualified expressions. There is no source-level import declaration; a legacy top-level `import` is a syntax error. Private declarations are module-local; a qualified reference that crosses a module or package boundary to a private declaration reports `E_ACCESS_PRIVATE`. Unknown aliases, modules, or declarations report `E_NAME_UNRESOLVED`. Package paths are local filesystem paths resolved relative to the declaring manifest. Path dependencies and exact-commit Git dependencies are implemented; registries and a public package-install service are not. Path dependencies work offline. Git dependencies work offline only when both the project lock and cached source/content checks pass; normal `check`, `build`, `run`, `test`, `inspect effects`, `inspect api`, and `audit` commands never invoke Git.

`lang audit PACKAGE_DIRECTORY --json` checks a package and its complete resolved local dependency graph, then emits deterministic schema-v9 JSON with package input hashes, compiler function/effect/capability facts, configuration schema metadata, root manifest grants, `http_origin`, and configured process executable pins in `process_executables`, followed by trusted-component claims and generated foreign dependencies. Its configuration metadata contains field names, declared types, and required/default status only; it does not expose runtime values or default literals. It includes private helper facts across the graph and keeps configured grants separate from inferred requirements. A successful managed or Native AOT `lang build` also writes a schema-v3 `build-receipt.json` beside the artifacts; package identities in both reports include a portable `source`: `{ kind: "root" }`, `{ kind: "path", path }`, or `{ kind: "git", url, commit }`. The identity `path` is a stable logical package ID: `.` for the root, a portable relative path for a path dependency, or `git:<64 lowercase hex SHA-256>` for Git. The Git ID derives from canonical URL and exact commit; it is not the physical cache path. Receipt v3 hashes the exact audit v9 snapshot. The receipt records build/toolchain inputs and hashes each output artifact by a relative path. The audit and receipt document compiler-derived facts and explicit trust claims; they do not prove adapter behavior, establish a sandbox, or promise reproducible binaries. See the [audit and receipt contract](docs/implementation-contract.md#audit-and-build-receipt-contract) for exact fields and ordering.

Run `lang lock PACKAGE_DIRECTORY` to resolve a package's complete local dependency graph and write its canonical `lang.lock`. Current schema v3 records source identity, content hashes, and stable logical package references: `.` for the root, portable relative paths for local path dependencies, and `git:<64 lowercase hex SHA-256>` for Git pins derived from canonical URL and exact commit. It contains no workspace-absolute or cache paths. `check`, `build`, `run`, `test`, `inspect effects`, `inspect api`, and `audit` require a current lock whenever the graph has dependencies; a missing, malformed, or stale lock reports `E_LOCK` and directs you to run `lang lock`. Dependency source line-ending-only rewrites and files under `out/` do not stale the lock. Dependency-free packages need no lockfile.

Workstation GC is the V1 default runtime policy, explicitly configured for the compiler and generated applications. Normal `lang build` and `lang run` stay managed. To publish an executable from a source file or CLI package with Native AOT, use `lang build FILE_OR_PACKAGE --aot --rid RID`; build `win-x64` on Windows or `linux-x64` on Linux with the matching .NET Native AOT toolchain. The AOT build requires either a supported zero-argument `main() -> i32|bool|Text` or a typed command in a standalone source module or CLI package's entry module. Web packages are managed-only. It writes a native executable into the usual unique output directory, reporting its absolute path as `Built native executable: <path>`; typed-command builds also retain `command-schema.json` beside it. SDK publish output, including compatibility warnings, remains visible on stderr as unstructured text; a successful publish does not guarantee a warning-free build. The executable remains GC-managed. Library-only packages and the compiler tool are not AOT targets; shared-library exports belong to the separate ABI1 proof. `E_BUILD_TARGET` reports an unsupported RID, a host OS/RID mismatch, a missing/malformed AOT option combination, or AOT requested for a program without a supported entrypoint. An unrelated malformed CLI invocation retains normal usage handling.

The CLI build/run/test commands work for the implemented source subset. [`examples/text-validation`](examples/text-validation) is a pure `lib` package with immutable `Normalized<T>` and `Validation<T>` values, a pure static `Normalize` trait and closed `Text` implementation, and generic `normalize<T: Normalize>` dispatch. Empty raw text returns `Invalid(NormalizeError.Empty)`; nonempty text is trimmed and returned inside `Normalized<Text>`. The generic `require<T, E>` helper and managed tests for trimming and typed `Option` values remain. Tests contain typed local setup and one final boolean `assert`; they are checked during normal library checks and builds, and `lang test PACKAGE_DIRECTORY` runs only that package's tests. Dependency tests are typechecked but are not run by the root package command. Runtime results are plain PASS/FAIL lines with source locations and a summary; there is no JSON result format, property-testing framework, or AOT test runner. Path dependencies remain editable local references; exact-commit Git dependencies use the cache only after the current project lock and source/content checks pass. Generic values remain internal library values: route and database codecs stay concrete. Generic inference and its current limits are described in [docs/grammar.md](docs/grammar.md). The maintained [`examples/scan-cli`](examples/scan-cli) package demonstrates an async typed command that awaits `FsRead.read_text_async`, with a CLI `fs.read` grant, injected `FsRead`, typed filesystem failures, strict UTF-8 decoding, and a local validation-library dependency.

The maintained [`examples/web`](examples/web) package demonstrates a managed route host with `net.listen`, `db.read`, `db.write`, and `fs.write` grants; an idempotent SQLite schema; parameterized `DbRead.query_one`, `DbWrite.execute`, and scoped transaction operations; JSON request/response structs; closed-union status mappings; safe `html.*` page builders; and the shared validation dependency. Its `POST /api/note` route awaits `FsWrite.write_text_async` to save strict-UTF-8 text through same-directory staging. Web integration coverage checks successful writes and overwrite behavior. A direct generated-adapter probe cancels at the `Task.Yield` checkpoint immediately after temporary-file creation and checks `OperationCanceledException`, preservation of prior contents, and temporary-file cleanup; existing host tests cover `RequestAborted` propagation through awaited calls. Routes support static paths and whole-segment `{name}` templates with `GET` and `POST`; a POST body is one supported struct. The maintained greeting API demonstrates `GET /api/greeting/{id}` with an integer path parameter, a required `name` query, and an optional `city` query. Missing or invalid bindings return stable 400 JSON, generated OpenAPI includes the parameters, placeholder names are unique case-insensitively, and equal-specificity template routes cannot collide. A route handler can receive optional `FsWrite`, `DbRead`, `DbWrite`, `HttpClient`, `Config`, `Secrets`, and `Logger` parameters after its optional request body, in that order, when the root web package grants those capabilities; `FsRead` is not injected into web handlers. `Config`, `Secrets`, `Logger`, and `Secret<Text>` are root-package-only. `HttpClient` uses the root package's `http_origin` for one outbound GET adapter; its request target must be an origin-relative absolute path with an optional query. Redirects, cookies, proxies, and credentials are disabled. Responses return `HttpResponse.status` and strict-UTF-8 `HttpResponse.body`, including non-2xx statuses; failures use the closed `HttpError` variants `InvalidTarget`, `Transport`, `Timeout`, `ResponseTooLarge`, and `InvalidText`. The body is limited to 1 MiB of raw bytes and the total request timeout is 10 seconds. The origin limits request authority but is not an SSRF or network sandbox; DNS resolution and trusted runtime code remain boundaries. `DbRead.query_one` accepts one SQL string literal beginning with `SELECT`, no semicolon, a concrete parameter struct, and a result type of `Result<Option<Row>, DbError>`; it checks column shape and accepts zero or one row. Transaction execution accepts one literal `INSERT`, `UPDATE`, `DELETE`, or `REPLACE` statement with no semicolon, preventing SQL from issuing its own transaction-control command; other forms report `E_DB_TRANSACTION_STATEMENT`. The first successful commit returns `Ok(true)`; an uncommitted scope rolls back on normal exit or early return. If an execute fails, the transaction becomes rollback-only and `tx.commit()` returns `Err(DbError.Statement)`, so earlier writes are rolled back when the scope exits. `Transaction` is a lexical handle: inside its scope it can only be the direct receiver of `execute` or `commit`; the checker rejects other uses with `E_RESOURCE_ESCAPE`. This rule applies only to transaction handles and is not general ownership or borrowing semantics. The sample reads and updates a singleton greeting row that persists across host restarts. `LANG_SQLITE_PATH` can override the configured database file for isolated runs. SQLite-enabled builds conditionally reference pinned `Microsoft.Data.Sqlite` 10.0.12; packages without SQLite configuration do not add that dependency. Its durable build directory includes deterministic `openapi.json`; the host accepts `--urls URL` after `lang run PACKAGE --`, limits request bodies to 1 MiB, returns 400 for malformed or incompatible JSON and 413 for oversized bodies, and returns 404/405 for unmatched paths or methods. Unexpected handler faults become a generic JSON 500 with a request ID. Async route handlers and helpers propagate ASP.NET `RequestAborted` through awaited calls; cancellation ends the request without a generic JSON 500. `FsWrite.write_text_async` is available to async CLI and web handlers; it checks cancellation around staging and before replacement, and removes a leftover same-directory temporary file best-effort on failure or cancellation. Full-value encoding, durable flush, and overwrite move are synchronous steps, so cancellation cannot interrupt those steps. The synchronous filesystem APIs remain available. SQLite source APIs remain synchronous. Generated SQLite operations currently block on provider calls. [Microsoft.Data.Sqlite documents that its async methods execute synchronously](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async); a source-level async SQLite surface is deferred until it can provide meaningful concurrency and cancellation cleanup. This bounded set of adapters does not complete M2 or the V1 promise.

The typed CLI command layer supports one command in an executable source module or CLI package's entry module. A declaration gives each argument, option, and flag help text; the compiler checks its generated `<PascalCaseName>Args` type against a fully qualified handler, which may be async, returning `Result<Text, E>` and a pure `E -> Text` error formatter. Handlers retain ordinary effect declaration and inference checks. A CLI package may grant `fs.read`, `fs.write`, `net.client`, `env.read`, `secret.reveal`, `log.write`, and/or CLI-only `process.spawn` with entries in `[capabilities]` assigned the exact string value `"allow"`; `net.client` also requires top-level `http_origin`. The generated command entry injects only granted services requested by the handler, after its generated arguments and in `FsRead`, `FsWrite`, `HttpClient`, `Config`, `Secrets`, `Logger`, then `ProcessRunner` order. Grants do not create a security sandbox. `lang run FILE_OR_PACKAGE -- APPLICATION_ARGS` forwards arguments to a typed command parser; Ctrl+C cancellation of an async command exits 130. Top-level and command `--help` exit 0; parse failures use stable `CLI_*` codes and exit 2; `Ok(Text)` writes stdout and exits 0; formatted `Err(E)` writes stderr and exits 3; unexpected runtime faults exit 70. Builds with typed commands emit deterministic `command-schema.json` version 4; its capability list records the handler-required services injected by the trusted command root, in handler parameter order, and omits unused grants. `lang inspect effects PACKAGE_DIRECTORY SYMBOL --json` provides a schema-v1 compiler-derived report of declared/inferred effects, shortest paths, required capabilities, manifest grants, and trusted runtime boundaries. `lang inspect api PACKAGE_DIRECTORY --json` provides deterministic, path-independent schema-v11 compiler metadata for public declarations across the root and its direct dependencies, plus the root package's checked command and route surface, `http_origin`, configuration schema metadata, and `process_executables`. Function records include `is_async`; command and route records include `handler_is_async`. Configuration metadata contains field names, declared types, and required/default status only, without runtime values or default literals. `lang audit PACKAGE_DIRECTORY --json` emits schema-v9 normalized hashes, configuration schema metadata, and checked function/effect/capability facts for the complete package graph, including private functions, root manifest grants, `http_origin`, `process_executables`, and claim-only trusted components. Audit and API reports keep configured grants separate from inferred effects and requirements. The successful-build receipt is schema v3, hashes its audit snapshot and output artifacts, and does not claim proof or binary reproducibility; see the [audit and receipt contract](docs/implementation-contract.md#audit-and-build-receipt-contract).
