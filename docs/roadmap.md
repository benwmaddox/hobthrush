# Roadmap and current claims

The Hobthrush source PRD lives in [PRD.md](PRD.md). The executable is `hob`, and source files use `.hob`. References to V1 below describe planned capability scope; the language is pre-1.0 and makes no backward-compatibility or migration promise.

## AI-operated development and evolution

The design direction gives AI systems control of detailed project work: evaluate and prioritize suggestions against human-set goals, design and implement accepted changes, test outcomes, independently review, and maintain the compiler and standard library. Compiler constraints, black-box tests, and CI gates govern acceptance; people provide high-level direction and inspect code only when needed. The repository does not yet automate this complete process. After 1.0, public syntax and semantics should change rarely; compiler, runtime, and tooling internals may improve more often behind observable contracts. AI systems should coordinate compatible standard-library growth when a feature fits there.

Filesystem read/write and SQLite operations are trusted adapter boundaries. `FsRead` reads the supplied path and decodes strict UTF-8. `FsWrite` encodes the entire value as strict UTF-8 without a BOM, stages it in a same-directory temporary file, and uses an overwrite move; replacement atomicity depends on the host OS and filesystem. Neither filesystem capability confines paths to a package root or creates a security sandbox. The pinned process binary retains full OS authority; the host does not provide CPU/memory isolation or guarantee termination of detached descendants. The ProcessRunner slice has no web support, streaming, dynamic executable selection, binary I/O, per-call timeout, or detached-work API. SQLite supports constrained literal SQL and typed parameters/rows for configured web packages and libraries; root grants and opaque capability values are compiler-checked, but do not sandbox trusted .NET code. The JSON logger writes deterministic `level`, `event`, and `detail` fields to stderr and adds `request_id` when a web request provides one. ## Managed .NET adapter packages (`#748` bounded slice)

The [foreign interop contract](foreign-interop.md#managed-net-adapter-package-contract-planned) specifies the implemented syntax and the broader review requirements. A `kind = "lib"` package can bind one public bodyless `pub adapter fn ... = "operation.id";` declaration to the trusted `hob.sha256-text.v1` catalog entry. Its `[managed_adapter]` table pins `bridge_id`, `target_framework = "net10.0"`, a package-relative assembly path, and the assembly SHA-256. The catalog fixes the operation, assembly identity, portability target `portable-anycpu-il`, and closure hash; users cannot select arbitrary CLR members or provide RID/closure overrides. Lock schema v3 binds the declaration and catalog resolution. Audit schema v11 and build receipt schema v4 record sorted managed adapter identities, closed signatures, effects/capability claims, assembly hashes, closure hash, and `claim_only` assurance. This is metadata for review: adapter code retains full process authority, and no OS sandbox or proof of implementation behavior is provided. Arbitrary CLR/C# imports remain outside the language.

## Later gates

The compiler supports managed `kind = "web"` packages with typed `GET`/`POST` route templates, path/query bindings, a checked `net.listen` grant, optional root `fs.write`, deterministic OpenAPI output, and safe Html builders. Path placeholders are whole segments with `Text` or `i32` values; query parameters use `Text`, `i32`, or optional `Option` forms. Missing required values and invalid or duplicate inputs return the stable JSON 400 response. The maintained [`examples/web`](../examples/web) package runs on the ASP.NET host, consumes the shared validation library, and demonstrates a dynamic greeting lookup by path ID with required `name` and optional `city` query filters, plus configured SQLite parameterized operations, strict row decoding, root grants, transaction-scoped writes, and durable state across host restarts. It also demonstrates an async `POST /api/note` filesystem write; web integration checks successful writes and overwrite. A direct generated-adapter probe cancels at the `Task.Yield` checkpoint immediately after temporary-file creation and checks `OperationCanceledException`, prior-content preservation, and temporary-file cleanup; separate host tests cover `RequestAborted` propagation. A route handler receives the POST body first when present, then path bindings in template order, query bindings in declaration order, and requested `FsWrite`, `DbRead`, `DbWrite`, `HttpClient`, `Config`, `Secrets`, and/or `Logger` capabilities in that order; `FsRead` is not available to web handlers, and `Config`, `Secrets`, `Logger`, and `Secret<Text>` remain root-package-only; libraries cannot use or expose these types. Equal-specificity overlapping route templates for the same method are rejected; different methods and a more-specific literal template may overlap. A `net.client` grant requires root `http_origin`. `DbRead.query_one` reads one literal `SELECT` with zero-or-one row cardinality; `DbWrite.execute` performs a parameterized write; `with db.begin() as tx` scopes write transactions and rolls back by default. Transaction execution is limited to one literal DML statement (`INSERT`, `UPDATE`, `DELETE`, or `REPLACE`) with no semicolon. Fixture 16 and integration coverage exercise `E_RESOURCE_ESCAPE`; the rule applies only to lexical `Transaction` handles and does not implement general ownership or borrowing. Transaction runtime tests cover commit, implicit rollback, early return, failed statements, runtime faults, cancellation unwind, and a subsequent successful commit. SQLite language APIs remain synchronous: generated code blocks on provider calls, and Microsoft.Data.Sqlite async methods execute synchronously, so there is no async SQLite source surface yet. A source-level async SQLite API remains deferred until it can provide meaningful concurrency and provider-level cancellation behavior. ASP.NET `RequestAborted` reaches async handlers and helpers, and cancellation ends without a generic 500; transaction cleanup during cancellation is covered by MS1 conformance. The bounded outbound HTTP client uses one configured origin and a GET-only operation; it limits authority but is not an SSRF or network sandbox, with DNS resolution and trusted runtime remaining boundaries. SQLite adapter async/cancellation APIs, other scoped-resource rules, remaining V1 application grants, registries, and public package installation remain future work. `hob audit` and successful-build receipts describe compiler facts and recognized trust boundaries but do not prove trusted runtime code safe, establish a sandbox, or complete M2 or the V1 promise; grants are not a sandbox. The SQLite adapter does not complete M2 or the V1 promise.

## MS1 - memory-semantics design (complete)

The source contract and current conformance are recorded in the [memory-semantics decision matrix](memory-and-performance.md#ms1-memory-semantics-design-complete). Ordinary values are immutable; assignments, parameters, and returns may share storage without exposing identity or aliasing. `var` rebinds a same-typed local. Equality is structural for the listed immutable value types and recursive through structs, unions, `Option`, `Result`, lists, and maps. Resource/capability values and nominal types whose actual stored fields or payloads contain a handle, `Secret<Text>`, and unconstrained type parameters are not equality-capable; a phantom type argument alone does not make a nominal value resource-bearing. Capability-bearing nominal values may still be declared, constructed, and returned outside the lexical `Transaction` handle rules. Lexical transactions cannot escape their owner scope and roll back on normal exit, returned errors, runtime faults, early return, or cancellation unwind. Adapter internals remain trusted code.

- [x] Decide assignment, parameter/return sharing, equality, and mutation semantics for current ordinary values and collections.
- [x] Implement immediate one-parameter expression-bodied lambdas: immutable captures have value semantics, `var` captures report `E_CLOSURE_CAPTURE_MUTABLE`, and resource captures are rejected.
- [x] Decide lexical transaction owner/escape behavior and verify cleanup on success, errors, early return, and cancellation unwind.
- [x] Record the foreign adapter trust boundary without extending ordinary values into a general ownership system.
- [x] Add positive and negative fixtures for current syntax and keep source semantics independent of emitted C# layout.

## GOV1 - public AI-operated stewardship experiment (proposed, not started)

The non-binding [public stewardship proposal](public-ai-stewardship.md) describes proposed funding mechanics for the AI-operated development model: AI systems assess fit, user need, compatibility, and maintenance cost; categorize and prioritize requests; and coordinate accepted technical work with independent AI review. Donations, sponsorships, grants, contracts, and milestone escrow may fund that work. Funding buys defined work, never technical acceptance. The proposal excludes cryptocurrency, tokens, tradable governance rights, financial-return promises, and sponsorship-weighted technical control.

GOV1 is not a V1 language gate. This roadmap entry does not authorize public fundraising.

- [ ] Demonstrate repeatable private planning, implementation, independent review, release, and maintenance records with measured model and infrastructure costs.
- [ ] Publish a versioned technical charter, contribution and licensing terms, conflict policy, security process, and conventional public accounting format.
- [ ] Establish the legal, fiduciary, credential, signing-key, privacy, tax, and refund boundaries before accepting public funds.
- [ ] Run an evidence-only period with no public funding, then review decision quality, estimate accuracy, and disclosure burden.
- [ ] Pilot shared maintenance sponsorship before accepting feature-specific review funding.
- [ ] Pilot capped technical-review sponsorship with public reports and no implementation promise.
- [ ] Allow milestone-funded implementation only for proposals already accepted through the public technical process, with an independent-review and maintenance allocation.
- [ ] Publish concentration, dispute, security, maintenance, and cost results before expanding the program.
