This is a partial M2 foundation, not M2 completion. Filesystem read/write and SQLite operations are trusted adapter boundaries. `FsRead` reads the supplied path and decodes strict UTF-8. `FsWrite` encodes the entire value as strict UTF-8 without a BOM, stages it in a same-directory temporary file, and uses an overwrite move; replacement atomicity depends on the host OS and filesystem. Neither filesystem capability confines paths to a package root or creates a security sandbox. The pinned process binary retains full OS authority; the host does not provide CPU/memory isolation or guarantee termination of detached descendants. The ProcessRunner slice has no web support, streaming, dynamic executable selection, binary I/O, per-call timeout, or detached-work API. SQLite supports constrained literal SQL and typed parameters/rows for configured web packages and libraries; root grants and opaque capability values are compiler-checked, but do not sandbox trusted .NET code. Managed adapters likewise execute with the process's full authority; their catalog, hashes, effects, and capability claims do not prove adapter behavior or provide an operating-system sandbox. `FsRead.read_text_async` is a strict-UTF-8 `fs.read` operation, and the bounded `HttpClient.get_text_async` operation is an awaited `net.client` GET with origin checks, byte and time limits, and host-cancellation propagation. The root-only configuration slice adds `Config.get_text` and `Config.get_secret_text` (`env.read`), `Secrets.reveal_text` (`secret.reveal`), and `Logger.info` (`log.write`). Config values are snapshotted once before CLI dispatch or web listen; required values are checked for presence and empty present values remain valid. Startup failures name only the field and derived environment variable; CLI exits 78 and web startup stops before listen. Secret formatting/logger output is redacted, while explicit reveal returns ordinary `Text` without taint tracking. The JSON logger writes deterministic `level`, `event`, and `detail` fields to stderr and adds `request_id` when a web request provides one. API schema v7 and audit schema v7 expose config field names, source types, and required/default status only; runtime values and default literals are omitted. They also expose configured process executable pins after `http_origin`. Command schema is v4, inspect-effects is v1, audit is v7, and build-receipt is v3. Metadata and grants do not provide OS-level containment. Existing `FsRead.read_text` and `FsWrite.write_text` remain synchronous language APIs; awaited `FsWrite.write_text_async` stages the same strict-UTF-8 write and checks cancellation before replacement. Encoding, durable flush, and overwrite move are synchronous and cannot be interrupted; a leftover temporary file is removed best-effort. SQLite language APIs remain synchronous. Generated SQLite operations block on provider calls; [Microsoft.Data.Sqlite's async methods execute synchronously](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/async). Source-level async SQLite is deferred pending meaningful concurrency and cancellation cleanup. Async functions retain source result types while the runtime carries hidden task and cancellation-token state. CLI Ctrl+C exits 130, and ASP.NET `RequestAborted` propagates through async handlers/helpers without turning cancellation into generic HTTP 500. Async/cancellation support for other adapters remains future `#743` work. Dynamic config reload, secret rotation, arbitrary logging maps or sinks, clock/timestamps, and end-to-end taint tracking remain future work. `lang audit` reports compiler-checked functions and explicit trusted integration claims; `build-receipt.json` hashes that audit snapshot and output artifacts. Neither proves adapter internals safe or claims that binaries are reproducible. Further `#743` slices cover the remaining effect classes. Source-level async SQLite stays deferred unless a design can provide meaningful concurrency and cancellation cleanup.

## Managed .NET adapter packages (`#748` bounded slice)

The [foreign interop contract](foreign-interop.md#managed-net-adapter-package-contract-planned) specifies the implemented syntax and the broader review requirements. A `kind = "lib"` package can bind one public bodyless `pub adapter fn ... = "operation.id";` declaration to the trusted `lang.sha256-text.v1` catalog entry. Its `[managed_adapter]` table pins `bridge_id`, `target_framework = "net10.0"`, a package-relative assembly path, and the assembly SHA-256. The catalog fixes the operation, assembly identity, portability target `portable-anycpu-il`, and closure hash; users cannot select arbitrary CLR members or provide RID/closure overrides. Lock schema v3 binds the declaration and catalog resolution. Audit schema v7 and build receipt schema v3 record sorted managed adapter identities, closed signatures, effects/capability claims, assembly hashes, closure hash, and `claim_only` assurance. This is metadata for review: adapter code retains full process authority, and no OS sandbox or proof of implementation behavior is provided. Arbitrary CLR/C# imports remain outside the language.

## Later gates

The compiler supports managed `kind = "web"` packages with typed `GET`/`POST` route templates, path/query bindings, a checked `net.listen` grant, optional root `fs.write`, deterministic OpenAPI output, and safe Html builders. Path placeholders are whole segments with `Text` or `i32` values; query parameters use `Text`, `i32`, or optional `Option` forms. Missing required values and invalid or duplicate inputs return the stable JSON 400 response. The maintained [`examples/web`](../examples/web) package runs on the ASP.NET host, consumes the shared validation library, and demonstrates a dynamic greeting lookup by path ID with required `name` and optional `city` query filters, plus configured SQLite parameterized operations, strict row decoding, root grants, transaction-scoped writes, and durable state across host restarts. It also demonstrates an async `POST /api/note` filesystem write; web integration checks successful writes and overwrite. A direct generated-adapter probe cancels at the `Task.Yield` checkpoint immediately after temporary-file creation and checks `OperationCanceledException`, prior-content preservation, and temporary-file cleanup; separate host tests cover `RequestAborted` propagation. A route handler receives the POST body first when present, then path bindings in template order, query bindings in declaration order, and requested `FsWrite`, `DbRead`, `DbWrite`, `HttpClient`, `Config`, `Secrets`, and/or `Logger` capabilities in that order; `FsRead` is not available to web handlers, and `Config`, `Secrets`, `Logger`, and `Secret<Text>` remain root-package-only; libraries cannot use or expose these types. Equal-specificity overlapping route templates for the same method are rejected; different methods and a more-specific literal template may overlap. A `net.client` grant requires root `http_origin`. `DbRead.query_one` reads one literal `SELECT` with zero-or-one row cardinality; `DbWrite.execute` performs a parameterized write; `with db.begin() as tx` scopes write transactions and rolls back by default. Transaction execution is limited to one literal DML statement (`INSERT`, `UPDATE`, `DELETE`, or `REPLACE`) with no semicolon. Fixture 16 and integration coverage exercise `E_RESOURCE_ESCAPE`; the rule applies only to lexical `Transaction` handles and does not implement general ownership or borrowing. The maintained web tests cover commit, implicit rollback, early return, failed-statement rollback, and rejection of a later commit. SQLite language APIs remain synchronous: generated code blocks on provider calls, and Microsoft.Data.Sqlite async methods execute synchronously, so there is no async SQLite source surface yet. A source-level async SQLite surface is deferred until a design can provide meaningful concurrency and cancellation cleanup. ASP.NET `RequestAborted` reaches async handlers and helpers, and cancellation ends without a generic 500; deterministic cancellation cleanup for SQLite transactions and other scoped resources remains an MS1 conformance item. The bounded outbound HTTP client uses one configured origin and a GET-only operation; it limits authority but is not an SSRF or network sandbox, with DNS resolution and trusted runtime remaining boundaries. SQLite adapter async/cancellation support, other scoped-resource rules, remaining V1 application grants, registries, and public package installation remain future work. `lang audit` and successful-build receipts describe compiler facts and recognized trust boundaries but do not prove trusted runtime code safe, establish a sandbox, or complete M2 or the V1 promise; grants are not a sandbox. The SQLite adapter does not complete M2 or the V1 promise.

## MS1 - memory-semantics design (incomplete)

MS1 remains incomplete and must precede SH1 and broader mutable-sharing or resource-lifetime semantics that would lock source behavior. The collections slice records a narrow local binding/rebinding decision in [the memory contract](memory-and-performance.md), but it does not establish a general borrow checker or ownership model.

- [ ] Decide assignment and parameter passing, copy/sharing, identity/equality, and mutation, including collections and closures.
- [ ] Decide single-owner/borrow/escape rules for lexical scoped handles only, cleanup on success/error/cancellation, and the interop trust boundary; do not extend ordinary GC-managed objects into a general ownership system.
- [ ] Mark unresolved choices explicitly and write positive/negative language conformance programs before adding mutable-sharing or scoped resource semantics.
- [ ] Keep source value, sharing, identity, equality, mutation, and resource semantics explicit and independent of emitted C# layout; do not promise a physical representation at the language level.

## PERF1 - performance evaluation (not started)

PERF1 is a measurement track, not a guarantee or V1 completion gate. See [the measurement contract](memory-and-performance.md).

- [ ] Compare representative executable CLI workloads built with the ordinary managed Workstation GC configuration and optional Native AOT on the matching host OS; include web/SQLite applications when they are available and AOT-compatible.
- [ ] Measure startup, bytes allocated per operation and collection counts, steady/peak memory, throughput, p95/p99 latency, published size, and build cost.
- [ ] Pin hardware, OS, .NET SDK, RID, native toolchain, workload and input versions; record warmup, repetitions, commands, and raw results.
- [ ] Record compatibility limits and unsupported adapters. Native AOT remains GC-managed, requires a supported RID and native toolchain, and does not cover library-only programs or the compiler tool. Make no numerical performance guarantee.

## ABI1 - C ABI interop proof (not started)

Specify one foreign-boundary contract shared by .NET adapters and C ABI calls. ABI1 is an isolated proof, not production syntax, package support, effect/capability enforcement, or a second backend. Its proposed Native AOT shared-library export is separate from the executable-only `lang build --aot` deployment mode. See [the foreign interop plan](foreign-interop.md).

- [ ] Demonstrate a contract containing signature identity, pinned library hash, library/symbol identity, target OS/architecture ABI and calling convention, ownership/lifetime, error mapping, declared effects, required capabilities, and separately marked trusted claims. Define buffer length/encoding and callback lifetimes as future contract areas, outside the scalar proof.
- [ ] Build a tiny C library from source with an `int32_t` identity function; demonstrate a checked language call through typed foreign IR and reject unsupported or mismatched scalar signatures.
- [ ] Export a pure checked language `i32` transform from a NativeAOT shared library with status plus a caller-owned synchronous `int32_t` out-parameter. Demonstrate that runtime overflow becomes an error status and no exception crosses the ABI. The out-parameter is valid only for the call and is never retained; no user-defined pointer ownership is supported.
- [ ] Call the exported language function from C and Python hosts. After control flow is supported, separately demonstrate a meaningful pure language validation library callable from those hosts; the scalar transform alone is not that demonstration.
- [ ] Pin SDK/toolchain, OS/architecture ABI, inputs and host versions; record raw call timings, artifacts/sizes, build cost, and deployment limits on Windows and Linux. This is bounded evidence, not completion of PERF1 or a backend switch.
- [ ] Keep normal `lang` commands closed to foreign imports. Gate richer effect/capability behavior on M2 and resource-lifetime semantics on MS1.

## SH1 - staged compiler self-hosting (not started)

SH1 is a follow-on after the M1 reusable-library path, M3 useful CLI, and MS1, once M2 effect/capability support is available. PERF1 results should inform its deployment choices. It may proceed alongside M4 and M5; it must not delay or replace their V1 acceptance. Prerequisites include usable control flow, `Text` and collections, generics, modules, diagnostics, and capability-controlled filesystem/process access. SH1 does not complete V1.

- [ ] Build a useful formatter or source tool in lang.
- [ ] Port the lexer and parser, with differential checks against the C# bootstrap.
- [ ] Port the checker, typed IR, and C# emitter; retain C# output and the .NET SDK/runtime. The first-party runtime may stay in C#.
- [ ] Keep stage 0 as the known-good C# bootstrap: it builds stage 1 from lang-authored compiler sources, and stage 1 rebuilds those same sources as stage 2.
- [ ] Pin the bootstrap/compiler sources, toolchain, dependencies, and conformance corpus. On Windows and Linux, run independent positive and negative constraint gates against both stages; compare stage 1 and stage 2 generated C# deterministically and compare behavior/diagnostics.
- [ ] Use only narrow path/line-ending normalization where required, without masking semantic differences; keep the C# bootstrap available for recovery until its replacement is separately justified.

This is a reproducibility and conformance gate, not a claim of identical binaries or a trust proof. It requires neither a native backend nor a rewritten runtime.
